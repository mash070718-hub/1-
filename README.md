# Library of Limbus

Library of Ruina풍의 개인 림버스 컴퍼니 평가 도서관입니다. 배포 주소는 **https://library-of-limbus.pages.dev/**입니다. Cloudflare Pages와 기존 GitHub Pages는 `library-of-limbus` 브랜치의 `/docs`를 배포합니다.

## 공용 도서관과 관리자

방문자는 로그인 없이 Supabase의 게시된 기록을 읽습니다. 관리자만 이메일·비밀번호로 로그인하여 임시 편집본을 작성하고 **게시하기 → 공개 게시 확인**으로 공개합니다. 관리자 권한은 브라우저 버튼 숨김 외에도 PostgreSQL RLS와 명시적인 관리자 사용자 ID로 보호합니다. 누구나 가입해서 관리자가 되는 기능은 없습니다.

**프로젝트 연결은 사용자 소유 Supabase 프로젝트를 만든 후 완료해야 합니다.** [실제 사이트의 관리자 연결 안내](https://mash070718-hub.github.io/1-/ADMIN_SETUP.html)에 가입부터 SQL 설치, 계정 생성, 공개 연결 정보 입력, 백업 가져오기까지 설명했습니다. 설치 SQL은 [supabase/setup.sql](supabase/setup.sql)입니다. `docs/cloud-config.json`이 Pages의 공개 연결 설정이고 `public/cloud-config.json`은 Vite 개발 환경용입니다. 연결 시 두 파일을 동일하게 유지하세요. 공개 Publishable/anon 키만 허용합니다. 비밀번호, secret 키, service_role 키는 포함하지 않습니다.

이 저장소의 초기 연결 파일은 비어 있습니다. 연결 전에는 공용 저장과 관리자 로그인이 준비되지 않았다는 안내가 나오며 편집할 수 없습니다. 도감은 열람할 수 있습니다. 데이터가 없는 상태를 게시 완료로 표현하지 않습니다.

## 기존 기록 보존과 가져오기

이전 브라우저 저장 키 `library-of-limbus:v1`을 수정하거나 삭제하지 않습니다. 기록을 작성하던 PC의 같은 브라우저에서 **백업과 복원 → 저장소 원본 다운로드**로 원본 JSON을 보관합니다. 이미 보관한 v1 백업도 사용할 수 있습니다.

연결 후 관리자 로그인 → 백업과 복원 → 백업 파일 선택 → 가져오기 확인으로 임시 편집본에 가져옵니다. 파일 전체를 검증한 뒤에만 교체하며 일반·거울던전 기록을 함께 보존합니다. 가져오기만으로 공개 기록을 변경하지 않습니다. 내용 확인 후 게시하세요.

관리자 임시 편집본은 별도의 `library-of-limbus:admin-draft:v1` 키에 보관합니다. 손상된 편집본은 덮어쓰지 않고 원본 다운로드와 정상 백업 복구를 제공합니다. 임시 편집본은 브라우저별로 독립적이고 공개 기록은 모든 기기에 공통입니다. 게시 충돌은 버전 검사로 거부하고 현재 편집본을 유지합니다. 로그인 토큰은 탭의 sessionStorage에 저장하고 갱신합니다. 로그아웃 후에는 공개 기록을 다시 표시합니다.

## 평가 기능

- 수감자별 출시 인격·E.G.O 도감, 공식 한국어 이름과 로컬 이미지, 신규 출시 자료 자동 확인
- 인격별 1동기화·3동기화 일러스트 선택, 목록·티어표·상세·일반/거울던전 편성과 덱 표지에 동일 적용
- 인격의 종합 티어는 콘텐츠별 티어와 별도로 수동 지정하며 기본 목록·티어표에 사용, 콘텐츠 탭으로 세부 티어 조회
- 기존 인격은 이전 기본 목록의 스토리 분류를 종합 티어로 한 번만 이어받고 이후 완전히 독립 저장
- 인격: 스토리 20·채광 10·사영전투 30·거굴철 10·거울던전 30점 만점으로 직접 입력, 종합 100점
- 거울굴절철도는 하나의 10점 만점 평가로 통합, 인격 목록·티어표에는 종합점수 표시 및 정렬
- 일반 인격 편집에서도 거울던전 30점 입력, 전용 화면과 같은 점수 사용; 거울던전 티어·공략 보존
- 덱의 콘텐츠별 수동 0~100점, 모든 점수에 소수점 허용, 0점과 미입력 구분
- 티어는 직접 지정, 같은 티어 내 점수 내림차순, 미입력은 마지막, 동점은 저장 순서 유지
- 일반 콘텐츠: 채광(경험치·끈), 스토리, 사영전투, 거울굴절철도(통합)
- 일반 덱 1~7번 편성 순서와 1번 이미지 표지, 사용 콘텐츠별 덱 찾기
- 별도 거울던전 메뉴와 독립된 덱·인격·E.G.O 편집·티어·노트·추천 E.G.O
- 거울던전 덱 S/A/B/C/D/미평가 티어리스트 및 점수 정렬, 일반 점수와 독립
- 거울던전 최대 12명 편성, 1~15층 테마팩·메모, 시작 기프트, 인격별 1·2·3스킬 개수
- 거울던전 덱마다 데미지 스크린샷 최대 3장, 사진 설명·확대 보기, 게시 전 비공개·게시 후 방문자 열람
- 실제 게임 태그 및 기타 ‘르루주’, ‘르누아르’, 이전 개인 태그 보존
- 인격 상세 장단점·운영·추천 E.G.O·사용 덱·편성번호, 기존 E.G.O 평가 유지

카탈로그의 최신 수록 수·출시일·고정 출처는 자동 생성되는 `docs/CATALOG_SOURCES.md`와 사이트의 ‘자료 출처와 수록 범위’에서 확인합니다. [출처와 갱신 절차](docs/CATALOG_SOURCES.md)를 참고하세요. 권리는 Project Moon에 있습니다. 개인 평가를 임의 생성하지 않습니다.

## 인격 일러스트 선택

관리자로 로그인하고 인격 상세의 **기록 수정**(첫 기록은 **평가 작성**)을 엽니다. **인격 일러스트**에서 1동기화 또는 3동기화를 고르고 **기록 저장 → 게시하기 → 공개 게시 확인**을 누릅니다. 선택값은 백업과 공개 데이터에 함께 저장되며, 이 인격을 1번으로 편성한 일반·거울던전 덱의 표지도 바뀝니다. 점수·티어·공략·편성 순서는 유지됩니다. 별도 3동기화 원화가 없는 기본 LCB 인격은 두 선택지에 같은 이미지를 표시합니다. 추가 Supabase 설정은 필요하지 않습니다.

## 신규 인격·E.G.O 자동 갱신

[Update Limbus catalog](https://github.com/mash070718-hub/1-/actions/workflows/update-catalog.yml)가 2시간 간격으로 출시 자료를 확인합니다. 공개 저장소의 GitHub Actions와 기존 Cloudflare Pages 무료 배포를 사용하며 별도 서비스 가입이나 API 키가 필요하지 않습니다.

- 출시 목록, 한국 날짜, 출시 예정 표시, 한국어 이름, 새 이미지의 형식·치수·해시를 검증합니다. 신규 인격의 1동기화·3동기화 이미지도 함께 준비합니다.
- 새로 출시된 항목은 미평가 상태로 추가합니다. Supabase 게시 데이터나 관리자 임시 편집본에 접근하지 않습니다.
- 기존 도감 ID가 미러에서 사라지거나 새 자료가 불완전하면 배포하지 않고 다음 예약 실행에서 다시 확인합니다.
- 자료가 같으면 파일 수정이나 재배포를 하지 않습니다. 기존 검증 이미지의 고정 출처는 유지합니다.
- 검사·브라우저 테스트·빌드를 통과해야 사이트 브랜치에 일반 push를 합니다. 다른 수정과 충돌하면 덮어쓰지 않고 다음 실행에서 다시 시도합니다.

예약 실행은 기본 브랜치 `main`의 `.github/workflows/update-catalog.yml`에서 시작하고, 실제 작업은 `library-of-limbus`를 체크아웃합니다. 두 브랜치의 워크플로 파일은 동일하게 유지합니다. 갱신 커밋은 Cloudflare Git 연동으로 배포되며 기존 GitHub Pages에는 명시적인 재빌드 요청을 보냅니다.

즉시 확인하려면 위 Actions 화면의 **Run workflow**를 누릅니다. GitHub가 예약 실행을 지연하거나 장기 비활동으로 비활성화할 수 있으므로, 실행이 멈춘 경우 같은 화면에서 상태를 확인하고 **Enable workflow**로 재개할 수 있습니다. 자료 미러의 갱신이 늦으면 게임 출시보다 사이트 반영도 늦습니다.

## 개발과 배포

거울던전 사진 첨부를 처음 사용할 때는 기존 Supabase 프로젝트에서 [supabase/screenshots.sql](supabase/screenshots.sql)을 한 번 실행합니다. 초보자용 [사진 저장소 설정 안내](https://library-of-limbus.pages.dev/SCREENSHOT_SETUP.html)에 복사 버튼과 단계별 순서가 있습니다. 기존 평가와 계정은 변경하지 않습니다. 사진 파일은 Supabase Storage에, 연결 정보와 설명은 기존 평가 데이터에 저장합니다. 백업 JSON에는 사진 원본이 들어가지 않으므로 저장소 파일을 유지하세요. 무료 플랜의 저장 공간·전송량 한도 안에서 사용할 수 있습니다.

Node.js 20.19 이상 또는 22.12 이상, Python 3, Chromium이 필요합니다. 기존 체크아웃을 사용하며 별도 Git worktree를 만들 필요는 없습니다.

```sh
cd /workspace/1-
npm ci --cache /workspace/.npm
npm run dev -- --port 5173 --strictPort
npm run build
npm test
npm run test:e2e -- --workers=2
npm run check:catalog
node scripts/build-standalone.mjs docs/index.html
```

`docs/index.html`은 공식 썸네일을 포함하는 Pages 배포용 단일 HTML입니다. 공용 저장·로그인은 인터넷과 Supabase 연결이 필요합니다. 단일 HTML 형태라는 이유로 오프라인 동기화를 제공하는 것은 아닙니다. 연결 설정과 관리자 안내 파일도 `/docs`에 함께 배포합니다. HTML 변경 후 `docs/manifest.json`의 해시와 바이트 크기도 갱신하세요.

브라우저 테스트는 시스템 `/usr/bin/chromium`을 사용합니다. 다른 경로는 `CHROMIUM_EXECUTABLE_PATH`로 지정할 수 있습니다. 브라우저 테스트의 Supabase HTTP 응답은 테스트용 모형입니다. 실제 DB 권한 검증 방법과 범위는 [supabase/README.md](supabase/README.md)에 있습니다. 사용자 프로젝트 연결 후 실제 Auth·게시·다른 기기 읽기 검증을 별도로 진행해야 합니다.
