관리자 로그인과 공용 저장소 연결

한 번 연결하면 같은 사이트 주소에서 관리자는 작성·게시하고, 방문자는 로그인 없이 공개 기록을 읽습니다. 방문자 브라우저에는 개별 평가를 저장하지 않습니다.

연결 전에는 게시와 로그인을 사용할 수 없습니다. PC에 있던 기존 기록은 삭제하지 않았습니다. 먼저 아래 1번에서 원본 백업을 보관하세요. 비밀번호·service_role·secret 키는 채팅이나 GitHub 파일에 넣지 마세요.

1. PC의 기존 기록 백업

  1. 기록을 작성하던 PC의 같은 브라우저에서 기존 사이트를 엽니다.
  2. 상단 ‘백업과 복원’ 버튼을 누르고 저장소 원본 다운로드를 누릅니다. 예전에 이미 다운로드한 JSON 파일도 사용할 수 있습니다.
  3. 이 JSON 파일을 안전하게 보관합니다. 이 단계는 공개 기록을 변경하지 않습니다. 브라우저 기록이 없는 기기에서는 ‘저장소 원본 다운로드’가 표시되지 않습니다.

2. Supabase 프로젝트 만들기

  1. Supabase 대시보드에 가입하거나 GitHub 계정으로 로그인합니다.
  2. New project를 누릅니다. 조직 생성 화면이 나오면 개인 조직을 만든 후 진행합니다. 프로젝트 이름은 library-of-limbus로 하셔도 됩니다.
  3. 데이터베이스 비밀번호는 새로 만들고 개인적으로 보관합니다. 지역은 가까운 곳을 선택하고 프로젝트가 준비될 때까지 기다립니다.
  4. 플랜과 요금은 생성 화면에서 확인하세요. 무료 플랜은 비활성 프로젝트가 일시 정지될 수 있으며, 그때는 대시보드에서 프로젝트를 재개해야 합니다.

3. 저장 테이블과 접근 권한 설치

왼쪽 SQL Editor → New query를 열고 다음 SQL 전체를 붙여넣은 후 Run을 누릅니다. 이미 설치한 프로젝트에서 재실행해도 게시 데이터는 지우지 않습니다.

4. 본인 관리자 계정 만들기

  1. Authentication → Users → Add user → Create new user로 이동합니다.
  2. 본인의 이메일과 사이트 로그인에 사용할 비밀번호를 입력합니다. Auto Confirm User 옵션이 있으면 켭니다. 이메일을 보낸다면 이메일 인증을 완료합니다.
  3. Authentication → Sign In / Providers → Email 또는 Authentication → Settings에서 신규 사용자 가입(Allow new users to sign up)을 끕니다. 이메일·비밀번호 로그인은 켜 둡니다. 메뉴 이름은 Supabase 버전에 따라 조금 다를 수 있습니다.
  4. 아래에 방금 만든 이메일을 입력하고 ‘관리자 등록 SQL 복사’를 누릅니다. SQL Editor의 새 쿼리에 붙여넣고 Run을 누릅니다. 결과에 본인 이메일이 1개 나오면 등록됐습니다.

가입 차단만으로 보호하는 것이 아닙니다. 데이터베이스의 관리자 목록과 RLS 접근 규칙이 실제 게시 권한을 제한합니다. 일반 계정은 스스로 관리자 권한을 부여할 수 없습니다.

5. 사이트에 공개 연결 정보 넣기

  1. 프로젝트의 Connect 창 또는 Project Settings → API / API Keys에서 Project URL과 Publishable key를 찾습니다. URL은 https://프로젝트ID.supabase.co, 공개 키는 보통 sb_publishable_…로 시작합니다. 예전 프로젝트의 anon public 키도 가능합니다.
  2. 아래 입력란에 두 값을 넣고 ‘연결 JSON 복사’를 누릅니다. 이것은 공개 연결 정보이며 관리자 비밀번호가 아닙니다. secret / service_role 키는 사용하지 않습니다.
  3. GitHub 연결 설정 편집 화면을 엽니다. GitHub 로그인 후 파일 전체를 복사한 JSON으로 바꿉니다.
  4. Commit changes를 누르고 Commit directly to the library-of-limbus branch를 선택하여 저장합니다. Pages 배포가 끝나면 사이트를 새로고침합니다. 연결 준비 중이라는 메시지가 사라지면 성공입니다.

GitHub 편집이 어려우면 Project URL과 Publishable key만 채팅으로 알려 주세요. 제가 연결 파일을 반영할 수 있습니다. 비밀번호나 secret/service_role 키는 보내지 마세요.

6. 기존 백업 가져오기와 첫 게시

  1. 사이트 상단 관리자 로그인에서 4번의 이메일·비밀번호로 로그인합니다.
  2. 백업과 복원 → 백업 파일 선택에서 1번 JSON을 선택합니다. 일반 기록·거울던전 기록 개수를 확인하고 가져오기 확인을 누릅니다.
  3. 이 단계는 임시 편집본만 교체합니다. 일반 기록과 거울던전의 편성·평가·공략이 모두 있는지 확인합니다. 누락이 있다면 게시하지 말고 원본 백업과 함께 알려 주세요.
  4. 게시하기 → 공개 게시 확인을 누릅니다. 이때 공개 기록 전체를 새 편집본으로 교체합니다. 이후 공개 백업도 별도로 보관하세요.
  5. 휴대폰 또는 시크릿 창에서 같은 사이트를 열어 로그인 없이 같은 기록이 표시되는지 확인합니다. 현재 열려 있는 방문자 화면은 ‘공개 기록 새로고침’으로 갱신할 수 있습니다.

매번 수정할 때

관리자 로그인 → 기록 수정 → 기록 저장 → 게시하기 → 공개 게시 확인 순서입니다. ‘기록 저장’은 이 브라우저의 임시 편집본이며, ‘게시하기’ 전에는 방문자에게 보이지 않습니다. 편집본은 다른 브라우저로 자동 이동하지 않으므로 먼저 게시하거나 백업하세요. 로그인은 탭을 닫으면 끝납니다.

인격 점수는 스토리 20점·채광 10점·사영전투 30점·거굴철 10점·거울던전 30점 만점으로 그대로 입력합니다. 다섯 콘텐츠를 더한 종합점수는 100점 만점이며, 거울굴절철도는 노선 구분 없이 하나의 10점 만점 평가로 합산합니다. 기존 기록은 이전에 합산하던 노선의 평가를 우선 이어받으며, 별도 선택이 없으면 6호선을 우선 사용합니다. 예전 노선별 원본 점수와 티어는 백업에 보존됩니다. 거울던전 점수는 일반 인격의 ‘기록 수정’에서도 입력할 수 있으며, 거울던전 전용 화면과 같은 점수를 사용합니다. 인격 목록과 티어표에는 종합점수가 표시되고, 같은 티어 안에서 종합점수순으로 정렬됩니다. 미완료 평가는 입력한 점수의 합계를 표시합니다. 기존에 입력한 숫자는 그대로 유지됩니다. 덱 점수는 0~100점입니다. 모든 점수에 소수점도 입력할 수 있습니다. 티어는 직접 정합니다. 같은 티어에서 점수 내림차순, 미입력은 마지막, 동점은 저장된 순서로 표시합니다. 일반 콘텐츠별 점수와 거울던전 점수는 분리됩니다. E.G.O. 평가는 기존 방식으로 유지됩니다.

다른 화면에서 먼저 게시해 충돌하면 내 편집본을 백업한 뒤 공개 기록을 다시 불러오고 변경 내용을 합쳐 게시하세요. 기존 브라우저 원본과 가져온 JSON 파일은 자동 삭제하지 않습니다.

문제가 생겼을 때

  • 연결 준비 중: 5번 JSON이 아직 비어 있거나 Pages 배포가 완료되지 않았습니다.
  • 관리자 편집 권한 없음: 4번 SQL의 이메일이 로그인 계정과 일치하는지 확인합니다.
  • 로그인 실패: 계정 이메일 인증·비밀번호·이메일 로그인 사용 여부를 확인합니다. 비밀번호는 Supabase Users에서 관리합니다.
  • 공용 저장소 요청 실패: 프로젝트가 일시 정지되지 않았는지, 3번 SQL 실행이 성공했는지, Project URL과 공개 키가 같은 프로젝트의 것인지 확인합니다.
  • 공개 기록이 없음: 관리자가 아직 첫 게시를 하지 않았습니다. 기존 백업은 자동 게시하지 않습니다.
